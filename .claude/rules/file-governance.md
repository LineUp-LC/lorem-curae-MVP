# File Governance

These constraints are non-negotiable. They apply to every task that creates or modifies files in this project.

## Hard Limits

### 1. Markdown Files: 500 Line Maximum

**No `.md` file anywhere in the project may exceed 500 lines.**

This applies to:
- Rule files in `.claude/rules/` and all subdirectories
- Documentation files
- Any `.md` file created, modified, or generated by any task

**Before writing or modifying any `.md` file:**
1. Estimate the line count BEFORE writing
2. If it will exceed 500 lines, split it into multiple files with logical groupings and shared prefixes (e.g., `04-tech-stack-frontend.md`, `04-tech-stack-backend.md`)
3. Each resulting file must independently stay under 500 lines

**After writing or modifying any `.md` file:**
1. Count the lines: `wc -l <file>`
2. If it exceeds 500 lines, stop and split it immediately
3. Do NOT proceed to the next task until the violation is resolved

**Target range:** 80–300 lines per file is ideal. 500 is the hard ceiling, not the goal.

### 2. Rule Folders: 100 File Maximum

**No single folder inside `.claude/rules/` may contain more than 100 `.md` files.**

This applies to:
- `.claude/rules/` (root)
- `.claude/rules/Brain/`
- `.claude/rules/` any other subdirectory

**Before creating new rule files:**
1. Count existing `.md` files in the target folder: `find <folder> -maxdepth 1 -name "*.md" | wc -l`
2. If adding files would exceed 100, either consolidate existing small files or use a new subfolder
3. Do NOT create the file if it would push the folder over 100

## Enforcement

When any task involves creating or editing `.md` files, run this validation before marking the task complete:

```bash
# Check all .md files for line count violations
echo "=== .md files exceeding 500 lines ==="
find . -name "*.md" -not -path "./node_modules/*" -not -path "./.git/*" | while read f; do
  lines=$(wc -l < "$f")
  if [ "$lines" -gt 500 ]; then
    echo "VIOLATION: $f — $lines lines (max 500)"
  fi
done

# Check rule folder file counts
echo "=== Rule folder file counts ==="
for dir in .claude/rules .claude/rules/*/; do
  if [ -d "$dir" ]; then
    count=$(find "$dir" -maxdepth 1 -name "*.md" | wc -l)
    echo "$count files in $dir"
    if [ "$count" -gt 100 ]; then
      echo "VIOLATION: $dir has $count files (max 100)"
    fi
  fi
done
```

**If any violation is found, fix it before completing the task. These limits are not suggestions.**

## Splitting Strategy

When a file needs to be split:

1. **Identify logical sections** — headers, topics, or functional groupings
2. **Use numbered prefixes** for ordering: `00-`, `01-`, `02-`, etc.
3. **Each file must be self-contained** — include 1-2 lines of shared context (e.g., project name, product name) rather than cross-referencing other files
4. **Create an `_index.md`** in the folder that lists all files with one-line descriptions
5. **Keep the original as a backup** until the split is verified complete

## Why These Limits Exist

- Files over 500 lines bloat context windows and degrade agent reasoning quality
- Large rule files force Claude Code to load irrelevant information for simple tasks
- Folders with 100+ files become unscannable and cause rule-loading slowdowns
- Modular files are easier to maintain, update, and version independently
